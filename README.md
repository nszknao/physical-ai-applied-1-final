# duckscout

MicroDuckが頭部カメラで赤い対象を探し、歩いて近づいて停止する、Physical AI応用1の最終課題プロジェクトです。歩行には公式の学習済み方策を使用し、対象検出・行動判断・シミュレーションとの接続を実装しています。

## セットアップ

Python 3.12とuvを使用します。以下はリポジトリのルートで実行してください。Python環境は `.venv/` に作成されます。

```sh
uv sync
uv run python scripts/fetch_assets.py
```

素材はPollen Roboticsの固定revisionから取得します（モデル・メッシュ・ライセンス42ファイルと、移動方策1ファイル、計約23 MB）。取得済みファイルは検証して再利用します。接続切断・タイムアウト・一時的なHTTPエラーは、1・2・4・8秒の間隔で最大4回再試行します。途中で停止しても同じコマンドで再開できます。破損や変更を検出した場合は上書きせず停止するため、表示された対象ファイルを確認し、必要なら退避して取得をやり直してください。

## モデル表示

macOSを含め、次のコマンドで起動します。macOSでの `mjpython` への切り替えは自動です。

```sh
uv run python -m duckscout
```

ロボット・床・正面の赤い対象物を一時停止状態で表示します。ウィンドウにフォーカスを合わせて操作してください。

| 操作 | 動作 |
|---|---|
| Space | 物理更新の再開・一時停止 |
| R | 初期姿勢へ戻して一時停止 |
| Esc／ウィンドウを閉じる | 終了 |

ビューアは公式XMLの位置制御を使用し、学習済み方策による姿勢維持は行いません。物理更新を再開すると倒れる場合があります。

初期姿勢は `--keyframe SIT` などで選べます。別のシーンには `--scene /absolute/path/to/scene.xml` を指定します。macOS以外でも同じコマンドを使用できます。

## 立位・前進・旋回・停止

```sh
uv run python -m duckscout --policy
```

取得済みの公式 `velstand.onnx` を使います。起動時は移動指令ゼロ・一時停止状態です。ウィンドウにフォーカスを合わせ、Spaceで物理更新を開始してください。

| 操作 | 動作 |
|---|---|
| ↑ | 前進（目標0.30 m/s） |
| ← | その場で左旋回（目標+0.80 rad/s） |
| → | その場で右旋回（目標−0.80 rad/s） |
| ↓ | 移動指令をゼロにして停止。姿勢制御は継続 |
| Space | シミュレーション時間の一時停止・再開 |
| R | 姿勢・移動指令・制御履歴を初期化し、一時停止 |
| Esc／ウィンドウを閉じる | 終了 |

矢印キーは一度押すと指令を保持し、次の矢印キーで置き換えます。前進中に←を押すと前進指令をゼロにして左旋回へ切り替わります。キーを離しても停止しないため、停止には↓を使ってください。一時停止中も指令は変更でき、Spaceで再開するとその指令で動きます。カメラはロボットの位置を追従します。

指令値と実速度は一致するとは限りません。停止指令後も減速・姿勢調整の動きがあり、微小な揺れが残る場合があります。転倒相当の高さ・傾き、非有限値を検出した場合はエラーを表示して終了します。

`--policy /path/to/velstand.onnx` で別の保存先も指定できます。同じ観測・関節・動作仕様の方策が必要で、任意のONNXモデルには対応しません。方策使用時の初期姿勢はSTANDに限定します。

ウィンドウを開かず、30秒分の立位を確認するには次を実行します。

```sh
uv run python -m duckscout --policy --headless --steps 6000
```

胴体の最低高さ・最大傾き・開始位置からの最大水平変位を出力します。方策使用時は物理200 Hz・推論50 Hzで動作し、モデル表示のみのモードとは1ステップの時間が異なります。`--auto` を付けないheadless起動では移動指令はゼロです。移動と停止のシナリオは下記の自動テストで実行します。判定条件と学習環境との差は[設計](docs/design.md#移動制御)を参照してください。

## 対象物と頭部カメラ

既定のシーンは `assets/scenes/search.xml` です。初期位置の正面80 cmに、一辺8 cmの赤い立方体を床へ固定しています。配置は `--target X Y` で変更できます。XMLを編集する場合、長さの単位はm、`size` は各辺の半分です。物体との衝突は有効です。

頭部視点で起動するには、次を実行してください。

```sh
uv run python -m duckscout --policy --camera head
```

起動直後は一時停止しています。Space・矢印キーによる操作は外部視点と同じです。左側の **Rendering → Camera** で `head_camera` と `Tracking`（外部追従視点）を切り替えられます。パネルが隠れている場合はTabで表示します。Trackingは選択中のbodyを追跡し、方策使用時は起動時に胴体を選択します。

**Enter** を押すと、その時点の頭部カメラ画像を `runs/head_camera.ppm`、検出結果付き画像を `runs/head_camera_detection.ppm` に保存します。表示中の視点に関係なく頭部画像を保存し、同じパスのファイルは上書きします。`--snapshot runs/another.ppm` で保存先を変えられます。PPMはRGBをそのまま保存する画像形式で、追加ライブラリは不要です。macOSでは次のコマンドでPNGへ変換できます。

```sh
sips -s format png runs/head_camera.ppm --out runs/head_camera.png
open runs/head_camera.png
```

RGB画像は320×240で、シミュレーション時間基準で10 Hzで取得します。一時停止中は定期取得も止まり、Enterで現在の画像を取得・保存します。ビューアの更新周期・表示領域の縦横比は保存画像とは異なります。元画像はビューアのUI・選択マーク・検出枠を含みません。

ウィンドウを開かず、2秒立位後の元画像と検出結果付き画像を保存する場合：

```sh
uv run python -m duckscout --policy --headless --steps 400 --snapshot runs/head_camera.ppm
```

画像保存を指定したheadless実行にはOpenGLの描画環境が必要です。`--snapshot` と `--auto` を付けないheadless実行は描画コンテキストを作りません。

## 対象検出

```sh
uv run python -m duckscout --policy
```

右下に頭部カメラ画像を表示し、赤い対象候補を**緑の枠**、その中心を**黄色の十字**で示します。上部の `x`・`y` は画像左上を原点とする中心座標、`area` は検出した赤い画素の数です。検出できない場合は枠が消えて `Target: not detected` と表示します。外部視点・頭部視点のどちらを選んでも、この小窓は頭部の画像を表示します。小窓への画像転送は画像更新時とウィンドウサイズ変更時に行います。小窓はウィンドウに合わせて拡縮しますが、認識には常に320×240の元画像を使います。

画像取得と同じ10 Hzで毎回検出します。一時停止中は最後の結果を表示し、リセットとEnterで画像・検出結果を更新します。Spaceで開始し、←／→で対象を視野外へ出してから戻すと、見失い・再検出を確認できます。動きを止めるには↓を使ってください。

`--auto` を付けない場合、移動は矢印キーで操作します。色に基づく検出なので、赤い別物体を区別することや、暗さ・照明変化への完全な対応はできません。

## 自動の探索・接近・停止

```sh
uv run python -m duckscout --policy --auto
```

起動時は一時停止しています。Spaceで開始すると、1秒間立位を整えてから対象を探します。対象を画像中央へ向けて前進し、推定距離が停止条件に入ると移動指令をゼロにして立位を維持します。右下の画像には現在の状態、推定距離（`~` は概算）、動作理由を表示します。

| 状態 | 動作 |
|---|---|
| SEARCH | 対象を探すためにその場旋回。検出が続くか確認するときは停止 |
| ALIGN | 対象が画像中央に来る方向へその場旋回 |
| APPROACH | 中央付近の対象へ前進。距離不明・見失い・到着確認中は停止 |
| ARRIVED | 到着判定後、移動指令ゼロで立位を維持 |
| TIMED_OUT | シミュレーション時間60秒で到着できなかったため停止 |
| MANUAL | 自動動作を解除し、矢印キーで操作 |

- **Space**：一時停止・再開。停止中は自動動作のタイマーも進みません。
- **↓**：自動動作を解除し、移動指令をゼロにします。
- **↑／←／→**：自動動作を解除し、そのキーの手動指令へ切り替えます。
- **R**：ロボットと判断状態を初期化し、自動動作を再び有効にして一時停止します。
- **Enter**：元画像と、状態・推定距離を含む検出結果付き画像を保存します。

見失ったフレームでは前進・旋回を止め、0.5秒戻らなければ探索へ戻ります。到着・時間切れ後は自動で再発進しません。立位方策と物理更新は継続します。

停止条件は、画像からの**推定距離40 cm以下**です。対象の高さ8 cmと画像の見かけの高さを使う概算で、実距離40 cmを保証しません。立方体の向き・頭の傾き・画像の切れによって誤差があり、対象が画像端で欠けた場合は距離不明として前進を止めます。

`--target X Y` でその実行だけ対象の配置を変えられます。単位はmで、初期ロボットの正面が+X、左が+Yです。例えば左前方に置く場合：

```sh
uv run python -m duckscout --policy --auto --target 0.4 0.7
```

右前方は `--target 0.4 -0.7`、背後は `--target -0.8 0` です。配置はシーン設定にのみ使い、自動判断には渡しません。`--camera head` も併用できます。

ウィンドウなしで自動動作を実行する場合は次を使います。毎回カメラ画像を取得するため、OpenGLの描画環境が必要です。最後に出力する状態で到着・時間切れ・途中終了を区別してください。

```sh
uv run python -m duckscout --policy --auto --headless --steps 12600 --snapshot runs/auto.ppm
```

## 実行ログ

```sh
uv run python -m duckscout --policy --auto --output runs/front-01
```

Spaceで開始し、確認したいところまで動かしてEscで終了します。`--output` は手動操作や方策なしのheadless実行にも使えます。記録を有効にしても、到着後の待ち時間や自動終了は追加しません。headlessは指定した `--steps` まで実行します。

| ファイル | 内容 |
|---|---|
| `config.json` | 起動引数、初期状態、関節の配列位置、制御・記録周期、コード／方策の識別情報、実行環境 |
| `records.jsonl` | 時系列データとイベント。1行が1件のJSON |

位置・姿勢・速度・移動指令はシミュレーション時間で10 Hz、開始時とリセット直後にも記録します。状態変更、一時停止・再開、手動指令、リセット、終了・エラーはイベントとして記録します。一時停止中は定期記録を増やしません。データは行ごとにファイルへ書き出され、実行中にも読めます。

```sh
tail -n 5 runs/front-01/records.jsonl
```

- `kind`：`sample` が時系列データ、`event` がイベント。
- `time_s`：シミュレーション時刻。Rで0へ戻るため、ログは行順に読み、`reset` イベントで区切ります。
- `qpos`：MuJoCoの関節位置・姿勢の配列。`config.json` の `joints` に各関節の開始インデックスを保存します。胴体の自由関節は世界位置3要素[m]と四元数4要素[w, x, y, z]です。
- `qvel`：関節速度の配列。自由関節は世界座標での並進速度3要素[m/s]と局所座標での角速度3要素[rad/s]です。回転関節の位置・速度はrad・rad/sです。
- `command`：方策への前進速度[m/s]と旋回速度[rad/s]。方策なしでは `null`。

`ARRIVED` などの状態名はそのまま記録し、成否の判定や集計は行いません。終了イベントの `reason` は `closed`・`interrupted`・`error` のいずれかです。ロガーはシミュレータの時計を直接参照しないため、このイベントの `time_s` は `null` とし、最後に記録した時刻を `last_record_time_s` に添えます。

既存の出力ディレクトリは上書きしません。Rや手動への切り替え後も同じログへ記録を続けます。別の実行は `runs/front-02` など新しい保存先で起動してください。

## 検証

```sh
uv run python scripts/fetch_assets.py --check
uv run python -m duckscout --headless --steps 300
uv run python -m unittest discover -s tests -v
uv run ruff check .
uv run ruff format --check .
```

`--check` はネットワークを使わず素材を検証します。`--headless` は物理更新と数値状態を確認します。`--policy` 併用時は高さ・傾きも検証します。表示やキー操作の確認は別途必要です。実方策のテストは素材取得後に実行され、ファイルがない場合はskipと表示されます。立位維持に加え、前進・左右旋回からの停止、旋回後の前進をシミュレーション時間で検証します。

### 検証結果

- 自動テスト84件が通過。Ruffのlint・format確認も通過。
- macOSのGUIで、立位・前進・旋回・停止、カメラ・検出表示、自動探索・接近・停止、実行ログを動作確認。
- 実際のMuJoCo物理・ONNX方策と投影画像を使った統合テストで、以下の結果を確認。

| 対象配置 (X, Y) [m] | 到着判定までの時間 [s] | 到着3秒後の状態 |
|---|---:|---|
| 正面 (0.8, 0) | 5.2 | 指令ゼロ・立位維持 |
| 左前方 (0.4, 0.7) | 7.5 | 指令ゼロ・立位維持 |
| 右前方 (0.4, -0.7) | 13.5 | 指令ゼロ・立位維持 |
| 背後 (-0.8, 0) | 9.8 | 指令ゼロ・立位維持 |

この試験の停止3秒後の実カメラ−対象中心距離は約0.55〜0.60 mです。画像からの推定40 cmと実距離には差があります。投影画像は照明・遮蔽・レンズメッシュを再現しておらず、この表は実描画での配置別性能を示すものではありません。

対象が映らない場合は60秒で時間切れとなり停止を維持します。また、実行ログの有無で同じステップ数を実行した際の最終位置・姿勢・速度が一致することを確認しています。
