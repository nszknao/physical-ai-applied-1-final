# duckscout

MicroDuckが頭部カメラで対象を認識して歩く、Physical AI応用1の最終課題プロジェクトです。公式の学習済み歩行方策と、ローカルのQwen3-VLによるボール・ゴール認識を組み合わせ、ボールを押してゴールへ入れる動作を実装しています。赤い対象への接近・停止も実行できます。

## セットアップ

Python 3.12とuvを使用します。以下はリポジトリのルートで実行してください。Python環境は `.venv/` に作成されます。

```sh
uv sync
uv run python scripts/fetch_assets.py
```

素材はPollen Roboticsの固定revisionから取得します（モデル・メッシュ・ライセンス42ファイルと、移動方策1ファイル、計約23 MB）。取得済みファイルは検証して再利用します。接続切断・タイムアウト・一時的なHTTPエラーは、1・2・4・8秒の間隔で最大4回再試行します。途中で停止しても同じコマンドで再開できます。破損や変更を検出した場合は上書きせず停止するため、表示された対象ファイルを確認し、必要なら退避して取得をやり直してください。

## モデル表示

macOSを含め、次のコマンドで起動します。macOSでの `mjpython` への切り替えは自動です。

```sh
uv run python -m duckscout
```

ロボット・床・正面の赤い対象物を一時停止状態で表示します。ウィンドウにフォーカスを合わせて操作してください。

| 操作 | 動作 |
|---|---|
| Space | 物理更新の再開・一時停止 |
| R | 初期姿勢へ戻して一時停止 |
| Esc／ウィンドウを閉じる | 終了 |

ビューアは公式XMLの位置制御を使用し、学習済み方策による姿勢維持は行いません。物理更新を再開すると倒れる場合があります。

初期姿勢は `--keyframe SIT` などで選べます。別のシーンには `--scene /absolute/path/to/scene.xml` を指定します。macOS以外でも同じコマンドを使用できます。

## 立位・前進・旋回・停止

```sh
uv run python -m duckscout --policy
```

取得済みの公式 `velstand.onnx` を使います。起動時は移動指令ゼロ・一時停止状態です。ウィンドウにフォーカスを合わせ、Spaceで物理更新を開始してください。

| 操作 | 動作 |
|---|---|
| ↑ | 前進（目標0.30 m/s） |
| ← | その場で左旋回（目標+0.80 rad/s） |
| → | その場で右旋回（目標−0.80 rad/s） |
| ↓ | 移動指令をゼロにして停止。姿勢制御は継続 |
| Space | シミュレーション時間の一時停止・再開 |
| R | 姿勢・移動指令・制御履歴を初期化し、一時停止 |
| Esc／ウィンドウを閉じる | 終了 |

矢印キーは一度押すと指令を保持し、次の矢印キーで置き換えます。前進中に←を押すと前進指令をゼロにして左旋回へ切り替わります。キーを離しても停止しないため、停止には↓を使ってください。一時停止中も指令は変更でき、Spaceで再開するとその指令で動きます。カメラはロボットの位置を追従します。

指令値と実速度は一致するとは限りません。停止指令後も減速・姿勢調整の動きがあり、微小な揺れが残る場合があります。転倒相当の高さ・傾き、非有限値を検出した場合はエラーを表示して終了します。

`--policy /path/to/velstand.onnx` で別の保存先も指定できます。同じ観測・関節・動作仕様の方策が必要で、任意のONNXモデルには対応しません。方策使用時の初期姿勢はSTANDに限定します。

ウィンドウを開かず、30秒分の立位を確認するには次を実行します。

```sh
uv run python -m duckscout --policy --headless --steps 6000
```

胴体の最低高さ・最大傾き・開始位置からの最大水平変位を出力します。方策使用時は物理200 Hz・推論50 Hzで動作し、モデル表示のみのモードとは1ステップの時間が異なります。`--auto` を付けないheadless起動では移動指令はゼロです。移動と停止のシナリオは下記の自動テストで実行します。判定条件と学習環境との差は[設計](docs/design.md#移動制御)を参照してください。

## ボールを押してゴールへ入れる（手動）

```sh
uv run python -m duckscout --policy --scene assets/scenes/penalty.xml
```

正面70 cmに直径8 cm・質量30 gのボール、正面1 mに内幅60 cmのゴールを配置します。ボールは足との接触で転がる物理オブジェクトです。歩行方策を使って押し進める動作で、専用のキック方策は使いません。

Spaceで開始し、約2秒立位を整えてから↑で前進します。←／→で方向を調整し、ボールが白いゴールラインを越えたら↓で停止します。キーの指令は次のキーまで持続します。Rはロボットとボールを初期位置へ戻して一時停止します。

全体を見るには **Rendering → Camera → field_camera** を選んでください。Tabでパネルを開閉できます。頭部カメラは近づいたボールが画面下へ外れるため、手動操作には外部視点を使います。既存の右下の小窓は赤色検出の表示で、ゴール判定は行いません。この手動起動では `--auto` は付けません。

モデルや追加素材の取得は不要です。ボール・ゴール・床はMuJoCoの標準形状で定義しています。

## VLMでボールをゴールへ押し込む（Apple Silicon Mac）

```sh
uv run --extra vision python -m duckscout --policy --soccer --output runs/soccer-01
```

`READY` が表示されたら **Space → 数字の8** で1回の自動試行を開始します。以降は8を連打せず待ってください。全体を見るには **Rendering → Camera → field_camera** を選びます。`--soccer` はVLMを有効にし、既定で `penalty.xml` を読み込みます。

| 状態 | 動作 |
|---|---|
| `SETTLING` / `THINKING` | 停止して撮影し、VLMでボール・ゴールを認識 |
| `MOVING` | 中央のボールへ2秒前進、左右なら1秒旋回。その後は停止して再観測 |
| `PUSHING` | 直前に中央で確認したボールが画面下端にかかったら、最大8秒前進して押す |
| `GOAL` | ボール全体がゴール開口内を通過した。移動指令をゼロにして立位維持 |
| `STOPPED` | 観測が不明、ゴールが中央でない、最大12観測、押し込み時間切れなどで停止 |

ゴールが中央に見える場合だけ移動します。完全に見失ったボールを追って前進し続けることはありません。`PUSHING` 中は再推論せず、得点または期限で止まります。通常の前進で足を接触させる動作であり、専用のキック動作ではありません。

↓は自動処理の中止、他の矢印キーは手動操作への切り替え、Spaceは中止して一時停止です。Rでロボット・ボール・得点判定をリセットし、再度Space → 8でやり直せます。`STOPPED` 後は8で新しい画像を撮って再試行できます。必要なら先に手動で位置を直してください。`GOAL` 後の再試行はRで初期化します。`--auto`・`--headless` とは併用できません。

正面にボールとゴールがある既定配置向けです。回り込みや蹴る方向の幾何学的な計画は行わず、初期配置・認識誤差・歩行の接触によって失敗することがあります。移動判断にはVLMによるボール・ゴールの方向と、同じ頭部画像の赤色領域による画像端の確認を使います。MuJoCoの実座標は得点評価にのみ使い、VLMが「入った」と回答しても得点にはしません。得点は右下・ターミナルに表示し、出力指定時はイベントとして記録します。

自動試験では画像投影による代用観測と実際の歩行方策・接触物理を組み合わせ、接近・押し込み・得点・減速を検証します。これはVLMの画像認識精度を保証する試験ではありません。

## VLMによる1回ずつの観測・移動（Apple Silicon Mac）

```sh
uv run --extra vision python -m duckscout --policy --vlm
```

`--vlm` の既定シーンはボールとゴールのある `penalty.xml` です。起動時は一時停止で、モデルをバックグラウンドでロードします。右下が `READY` になったらSpaceで物理更新を開始し、**数字の8** を押します。NはMuJoCo標準のIsland色分け表示です。

8を受け付けると移動指令をゼロにし、0.5秒の整定待ち後に新しい頭部画像を取得します。初回・リセット後は最低2秒立位を整えてから撮影します。推論中は立位を維持し、回答に応じて一度だけ1秒動いて停止します。時間の指定はシミュレーション時間です。推論時間・待機表示は実時間です。

| 観測 | 移動指令 |
|---|---|
| ボールが画像端で切れず、左にある | 左旋回 +0.80 rad/s |
| ボールが画像端で切れず、中央にある | 前進 0.30 m/s |
| ボールが画像端で切れず、右にある | 右旋回 −0.80 rad/s |
| 見えない・不明・画像端で切れる・色検出と方向が不一致・不正な回答 | 指令ゼロ |

VLMはボール・ゴールの方向を返します。同じ画像の色検出で画像端との接触を確認し、Python側で移動方向を決めます。このモードはボールへの短い接近操作で、ゴールの認識位置は表示・記録用です。ゴールとの位置合わせ、接触時の押し込み、得点判定は行いません。停止後は次の8を待ち、自動反復しません。処理中に押した8は予約されません。

| 操作 | 動作 |
|---|---|
| 8 | 実行中・READYのとき、観測と短い移動を1回開始 |
| ↓ | 処理をキャンセルして停止。立位制御は継続 |
| ↑／←／→ | 処理をキャンセルして手動操作へ切り替え |
| Space | 処理をキャンセルして指令ゼロ。一時停止・再開 |
| R | 処理をキャンセルし、ロボットとボールを初期化して一時停止 |
| Esc／ウィンドウを閉じる | 終了 |

`LOADING` はモデル取得・ロード、`SETTLING` は撮影前の整定待ち、`THINKING` は推論、`MOVING` は1秒の移動、`READY` は次の8待ちです。右下に待機秒数・直近の推論秒数・観測結果・適用した行動を表示します。`ERROR` はターミナルに詳細を表示し、VLM操作を停止します。手動操作は継続できます。

推論ワーカーは1本で、表示・物理・歩行方策と並行して動作します。キャンセル後の回答は破棄し、実行中の推論が終わるまでは `CANCELLING` と表示します。ウィンドウを閉じても実行中の推論を強制中断しないため、ターミナルに戻るまで完了を待つ場合があります。推論中は頭部カメラの取得を10 Hzから2 Hzへ落としてGPU転送を減らします。推論速度そのものや実時間での物理更新速度はMacの性能に依存します。

`--output runs/visual-step-01` を追加すると、通常の状態ログに加えて、モデル・プロンプト・指令設定とVLMの回答、取得時刻、推論秒数、入力処理・生成のtokens/s、MLXピーク使用メモリ、適用した行動を記録します。`vision/0001.ppm` などに推論に使った元画像も保存します。`--camera head` で頭部視点からも確認できます。`--auto`・`--headless` とは併用できません。

移動指令だけを確認する場合は、GPU・VLM・ウィンドウを使わず次を実行できます。

```sh
uv run python scripts/check_visual_motion.py
```

2秒立位・1秒移動・2秒整定後の変位と向きの変化を出力します。基準配置での前進変位は約7.2 cmです。歩行方策の応答には左右差があり、同じ時間・旋回指令でも実際の旋回量は一致しません。

## 保存画像のVLM推論（Apple Silicon Mac）

[Qwen3-VL-4B-InstructのMLX 4bit版](https://huggingface.co/mlx-community/Qwen3-VL-4B-Instruct-4bit)をローカルで実行します。画像からボール・ゴールの方向を出力し、色検出による画像端の確認を加えます。確認スクリプトは本体と同じ規則で行動を算出しますが、シミュレータへ指令を送りません。

```sh
uv sync --extra vision
uv run --extra vision python -m duckscout --policy --scene assets/scenes/penalty.xml --snapshot runs/penalty.ppm
```

ビューアでEnterを押して頭部画像を保存し、Escで終了します。次に推論します。

```sh
uv run --extra vision python scripts/check_vision.py runs/penalty.ppm --output runs/vision-02
```

初回は固定revisionの重みなど約3 GBをHugging Faceのキャッシュへ取得します。以降はキャッシュを再利用します。実行時には重み以外にもメモリを使い、処理時間はMacの性能に依存します。通常の `uv run` は追加依存を外す場合があるため、画像推論には毎回 `--extra vision` を付けてください。

ターミナルのJSONと `runs/vision-02/result.json` に、生の回答 `raw_response`、検証済みの `observation`、推論秒数、モデルrevision、プロンプト、入力画像のSHA-256を記録します。`input-01.png` は推論に渡したRGB画像です。`--output` を省略するとターミナルへだけ出力します。既存の出力ディレクトリは上書きしません。

| 出力 | 意味 |
|---|---|
| `ball_position` / `goal_position` | 画像を横に3等分した `left` / `center` / `right`、映っていない `not_visible`、不明 `unknown` |
| `ball_inside_image` | VLMの方向と一致する赤色領域が画像端に接していない |
| `ball_at_bottom` | 同じ赤色領域が画像の最下行に接している（左右・上端には接していない） |
| `action` | Python側で観測から決めた `forward` / `turn_left` / `turn_right` / `stop` |
| `validation_error` | JSONの形式・値の検証エラー。正常時はnull |

モデルの回答は `{"ball_position":"center","goal_position":"center"}` のような2項目のJSONです。`ball_inside_image` と `ball_at_bottom` は画像の赤色領域から追加します。VLMがボールを見つけられない場合、赤色領域がない場合、左右方向が一致しない場合は両方falseにして停止します。色検出だけでVLMの方向を置き換えることはありません。赤いボール1個の既定シーン向けで、遮蔽物による隠れ方や複数の同色物体は扱いません。

JSONとして不正な回答は生の回答を残し、`observation` をnull、終了コードを1にします。形式の検証は画像認識の正しさを保証しません。元画像と回答を見比べてください。PNG・JPEG・PPMに対応し、長辺320画素を超える画像は縦横比を保って縮小します。検出枠付きの `_detection.ppm` ではなく、元画像を入力します。

`python scripts/check_vision.py a.ppm b.ppm` のように複数画像を渡すと、モデルを一度ロードして順番に推論します。本体の起動は `python -m duckscout`、画像の動作確認はこのスクリプトで行います。

中央・左・右・視野外・下端で切れる配置の5ケースを撮影して比較する場合：

```sh
uv run --extra vision python scripts/check_vision.py --cases --output runs/vision-check-01
```

ボールをそれぞれ(0.7, 0)、(0.7, 0.2)、(0.7, −0.2)、(−0.7, 0) mへ配置し、各ケースでリセット後に2秒立位を整えて撮影します。ゴールは固定です。配置座標は推論には渡しません。頭部画像は `frames/`、入力画像と推論結果は `analysis/` に保存します。撮影にはOpenGL、推論にはMetalを利用できるローカル環境が必要です。推奨行動は実行しません。

5ケースでは中央→前進、左→左旋回、右→右旋回、視野外→停止、下端で切れる配置→ `ball_at_bottom=true` を期待します。画像確認スクリプトの `action` は単発操作の規則なので、下端で切れる場合は停止です。自動ペナルティでは直前の接近確認も満たすと押し込みへ進みます。認識結果が正しいとは限らないため、生の回答を画像と照合してください。

## 対象物と頭部カメラ

既定のシーンは `assets/scenes/search.xml` です。初期位置の正面80 cmに、一辺8 cmの赤い立方体を床へ固定しています。配置は `--target X Y` で変更できます。XMLを編集する場合、長さの単位はm、`size` は各辺の半分です。物体との衝突は有効です。

頭部視点で起動するには、次を実行してください。

```sh
uv run python -m duckscout --policy --camera head
```

起動直後は一時停止しています。Space・矢印キーによる操作は外部視点と同じです。左側の **Rendering → Camera** で `head_camera` と `Tracking`（外部追従視点）を切り替えられます。パネルが隠れている場合はTabで表示します。Trackingは選択中のbodyを追跡し、方策使用時は起動時に胴体を選択します。

**Enter** を押すと、その時点の頭部カメラ画像を `runs/head_camera.ppm`、検出結果付き画像を `runs/head_camera_detection.ppm` に保存します。表示中の視点に関係なく頭部画像を保存し、同じパスのファイルは上書きします。`--snapshot runs/another.ppm` で保存先を変えられます。PPMはRGBをそのまま保存する画像形式で、追加ライブラリは不要です。macOSでは次のコマンドでPNGへ変換できます。

```sh
sips -s format png runs/head_camera.ppm --out runs/head_camera.png
open runs/head_camera.png
```

RGB画像は320×240で、シミュレーション時間基準で10 Hzで取得します。一時停止中は定期取得も止まり、Enterで現在の画像を取得・保存します。ビューアの更新周期・表示領域の縦横比は保存画像とは異なります。元画像はビューアのUI・選択マーク・検出枠を含みません。

ウィンドウを開かず、2秒立位後の元画像と検出結果付き画像を保存する場合：

```sh
uv run python -m duckscout --policy --headless --steps 400 --snapshot runs/head_camera.ppm
```

画像保存を指定したheadless実行にはOpenGLの描画環境が必要です。`--snapshot` と `--auto` を付けないheadless実行は描画コンテキストを作りません。

## 対象検出

```sh
uv run python -m duckscout --policy
```

右下に頭部カメラ画像を表示し、赤い対象候補を**緑の枠**、その中心を**黄色の十字**で示します。上部の `x`・`y` は画像左上を原点とする中心座標、`area` は検出した赤い画素の数です。検出できない場合は枠が消えて `Target: not detected` と表示します。外部視点・頭部視点のどちらを選んでも、この小窓は頭部の画像を表示します。小窓への画像転送は画像更新時とウィンドウサイズ変更時に行います。小窓はウィンドウに合わせて拡縮しますが、認識には常に320×240の元画像を使います。

画像取得と同じ10 Hzで毎回検出します。一時停止中は最後の結果を表示し、リセットとEnterで画像・検出結果を更新します。Spaceで開始し、←／→で対象を視野外へ出してから戻すと、見失い・再検出を確認できます。動きを止めるには↓を使ってください。

`--auto` を付けない場合、移動は矢印キーで操作します。色に基づく検出なので、赤い別物体を区別することや、暗さ・照明変化への完全な対応はできません。

## 自動の探索・接近・停止

```sh
uv run python -m duckscout --policy --auto
```

起動時は一時停止しています。Spaceで開始すると、1秒間立位を整えてから対象を探します。対象を画像中央へ向けて前進し、推定距離が停止条件に入ると移動指令をゼロにして立位を維持します。右下の画像には現在の状態、推定距離（`~` は概算）、動作理由を表示します。

| 状態 | 動作 |
|---|---|
| SEARCH | 対象を探すためにその場旋回。検出が続くか確認するときは停止 |
| ALIGN | 対象が画像中央に来る方向へその場旋回 |
| APPROACH | 中央付近の対象へ前進。距離不明・見失い・到着確認中は停止 |
| ARRIVED | 到着判定後、移動指令ゼロで立位を維持 |
| TIMED_OUT | シミュレーション時間60秒で到着できなかったため停止 |
| MANUAL | 自動動作を解除し、矢印キーで操作 |

- **Space**：一時停止・再開。停止中は自動動作のタイマーも進みません。
- **↓**：自動動作を解除し、移動指令をゼロにします。
- **↑／←／→**：自動動作を解除し、そのキーの手動指令へ切り替えます。
- **R**：ロボットと判断状態を初期化し、自動動作を再び有効にして一時停止します。
- **Enter**：元画像と、状態・推定距離を含む検出結果付き画像を保存します。

見失ったフレームでは前進・旋回を止め、0.5秒戻らなければ探索へ戻ります。到着・時間切れ後は自動で再発進しません。立位方策と物理更新は継続します。

停止条件は、画像からの**推定距離40 cm以下**です。対象の高さ8 cmと画像の見かけの高さを使う概算で、実距離40 cmを保証しません。立方体の向き・頭の傾き・画像の切れによって誤差があり、対象が画像端で欠けた場合は距離不明として前進を止めます。

`--target X Y` でその実行だけ対象の配置を変えられます。単位はmで、初期ロボットの正面が+X、左が+Yです。例えば左前方に置く場合：

```sh
uv run python -m duckscout --policy --auto --target 0.4 0.7
```

右前方は `--target 0.4 -0.7`、背後は `--target -0.8 0` です。配置はシーン設定にのみ使い、自動判断には渡しません。`--camera head` も併用できます。

ウィンドウなしで自動動作を実行する場合は次を使います。毎回カメラ画像を取得するため、OpenGLの描画環境が必要です。最後に出力する状態で到着・時間切れ・途中終了を区別してください。

```sh
uv run python -m duckscout --policy --auto --headless --steps 12600 --snapshot runs/auto.ppm
```

## 実行ログ

```sh
uv run python -m duckscout --policy --auto --output runs/front-01
```

Spaceで開始し、確認したいところまで動かしてEscで終了します。`--output` は手動操作や方策なしのheadless実行にも使えます。記録を有効にしても、到着後の待ち時間や自動終了は追加しません。headlessは指定した `--steps` まで実行します。

| ファイル | 内容 |
|---|---|
| `config.json` | 起動引数、初期状態、関節の配列位置、制御・記録周期、コード／方策の識別情報、実行環境 |
| `records.jsonl` | 時系列データとイベント。1行が1件のJSON |

位置・姿勢・速度・移動指令はシミュレーション時間で10 Hz、開始時とリセット直後にも記録します。状態変更、一時停止・再開、手動指令、リセット、終了・エラーはイベントとして記録します。一時停止中は定期記録を増やしません。データは行ごとにファイルへ書き出され、実行中にも読めます。

```sh
tail -n 5 runs/front-01/records.jsonl
```

- `kind`：`sample` が時系列データ、`event` がイベント。
- `time_s`：シミュレーション時刻。Rで0へ戻るため、ログは行順に読み、`reset` イベントで区切ります。
- `qpos`：MuJoCoの関節位置・姿勢の配列。`config.json` の `joints` に各関節の開始インデックスを保存します。胴体の自由関節は世界位置3要素[m]と四元数4要素[w, x, y, z]です。
- `qvel`：関節速度の配列。自由関節は世界座標での並進速度3要素[m/s]と局所座標での角速度3要素[rad/s]です。回転関節の位置・速度はrad・rad/sです。
- `command`：方策への前進速度[m/s]と旋回速度[rad/s]。方策なしでは `null`。

`ARRIVED` などの状態名はそのまま記録し、成否の判定や集計は行いません。終了イベントの `reason` は `closed`・`interrupted`・`error` のいずれかです。ロガーはシミュレータの時計を直接参照しないため、このイベントの `time_s` は `null` とし、最後に記録した時刻を `last_record_time_s` に添えます。

既存の出力ディレクトリは上書きしません。Rや手動への切り替え後も同じログへ記録を続けます。別の実行は `runs/front-02` など新しい保存先で起動してください。

## 検証

```sh
uv run python scripts/fetch_assets.py --check
uv run python -m duckscout --headless --steps 300
uv run python -m unittest discover -s tests -v
uv run ruff check .
uv run ruff format --check .
```

`--check` はネットワークを使わず素材を検証します。`--headless` は物理更新と数値状態を確認します。`--policy` 併用時は高さ・傾きも検証します。表示やキー操作の確認は別途必要です。VLMの実前処理テストは `uv run --extra vision python -m unittest discover -s tests -p test_vision.py -v` で実行できます。vision依存または固定revisionのモデルキャッシュがない場合、この実前処理テストはskipします。実方策のテストは素材取得後に実行され、ファイルがない場合はskipと表示されます。立位維持に加え、前進・左右旋回からの停止、旋回後の前進をシミュレーション時間で検証します。

### 検証結果

- 自動テスト114件が通過。Ruffのlint・format確認も通過。
- macOSのGUIで、立位・前進・旋回・停止、カメラ・検出表示、自動探索・接近・停止、実行ログを動作確認。
- 実際のMuJoCo物理・ONNX方策と投影画像を使った統合テストで、以下の結果を確認。

| 対象配置 (X, Y) [m] | 到着判定までの時間 [s] | 到着3秒後の状態 |
|---|---:|---|
| 正面 (0.8, 0) | 5.2 | 指令ゼロ・立位維持 |
| 左前方 (0.4, 0.7) | 7.5 | 指令ゼロ・立位維持 |
| 右前方 (0.4, -0.7) | 13.5 | 指令ゼロ・立位維持 |
| 背後 (-0.8, 0) | 9.8 | 指令ゼロ・立位維持 |

この試験の停止3秒後の実カメラ−対象中心距離は約0.55〜0.60 mです。画像からの推定40 cmと実距離には差があります。投影画像は照明・遮蔽・レンズメッシュを再現しておらず、この表は実描画での配置別性能を示すものではありません。

対象が映らない場合は60秒で時間切れとなり停止を維持します。また、実行ログの有無で同じステップ数を実行した際の最終位置・姿勢・速度が一致することを確認しています。
