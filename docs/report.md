# 見て選び、歩いて押すMicroDuckのボール操作

## 1. 課題の概要と目的

MuJoCo上の二足歩行ロボットMicroDuckに、赤・青の2球から文章で指定した色の球を選び、頭部カメラを使って接近し、足で押してゴールへ入れるタスクを実行させる。既存の視覚言語モデル（VLM）と学習済み歩行方策を組み合わせ、画像と言語による対象認識を物理的な行動につなぐことを目的とした。

赤球と青球を左右に置いたシーンで「青い球をゴールへ押す」という指示を与え、実VLMによる観測から旋回・接近・押し込み・得点後の停止まで成功した1試行を確認した。赤球は初期位置に残った。静止画像では赤・青の指示と配置を変えた8件中7件が期待値に一致した。

正面の球へ直進するだけの課題では、画像を見なくても成功しうる。同じ画像に異なる色の指示を与え、左右の配置も入れ替えることで、画像と指示に応じて行動候補が変わることを確かめた。

## 2. AIの活用とシステム構成

本課題では既存モデルの推論を利用し、新たな学習やファインチューニングは行っていない。ロボットのモデルと歩行方策にはPollen Roboticsの公開資産を使用した。[MicroDuck公式学習環境](https://github.com/pollen-robotics/microduck_rl)

| 要素 | 役割 | 利用・実装の区分 |
|---|---|---|
| Qwen3-VL-4B-InstructのMLX 4bit版 | 画像と文章から、指定した球とゴールの左右方向を認識 | 公開モデルを利用 |
| `velstand.onnx` | 前進・旋回の指令とロボットの状態から関節動作を生成 | 公開済みの歩行方策を利用 |
| BAM XL330 M6 | サーボの摩擦などを含む関節の物理応答を扱う | 既存ライブラリを利用 |
| MuJoCo | ロボット・球・ゴールの接触と運動を計算 | 既存シミュレータを利用 |
| 行動制御・評価処理 | 観測から移動を切り替え、得点・停止を判定 | 自作 |
| シーン・確認用スクリプト | 球とゴールの配置、指示を変えた比較 | 自作 |

VLMにはローカル実行できる[MLX形式の4bitモデル](https://huggingface.co/mlx-community/Qwen3-VL-4B-Instruct-4bit)を用いた。BAMはタスクの行動を決めるモデルではなく、関節を駆動する際の物理応答を扱う。[BAM公式リポジトリ](https://github.com/Rhoban/bam)

```text
頭部画像 ＋ 対象を指定する文章
    ↓
VLM：指定した球とゴールの左右方向
    ↓
指定色の画素追跡・画像端の確認 ＋ 行動規則
    ↓
前進速度・旋回速度の指令
    ↓
学習済み歩行方策 → 関節制御 → 球との接触・運動
    └────────────────→ 次の頭部画像
```

VLMが関節動作を直接生成する構成ではない。画像・言語から動作を一体的に出力するVLAモデルを学習したものではなく、VLM、行動規則、学習済み歩行方策を組み合わせている。

## 3. 自作した部分と工夫

### 推論中も立位を維持する

物理更新は200 Hz、歩行方策は50 Hzで動かし、数秒かかるVLM推論は別のワーカーで実行する。推論待ちの間は移動指令をゼロにして、姿勢制御を続ける。

停止・撮影・推論・短時間の移動を繰り返す。指定色の球を画像処理で追跡し、左右なら旋回、中央なら1秒前進して再観測する。接近した球が中央の画像下端にかかったら、最大8秒の前進で押し込む。専用のキック動作を作らず、既存の歩行による足との接触を利用した。

### VLMと画像処理の役割を分ける

320×240画素の画像を入力し、VLMの出力を `ball_position` と `goal_position` のJSONに限定する。値は画像の横3分割に対応する左右・中央と、不在・不明とし、説明文や移動指令そのものは生成させない。生成条件はtemperature=0、最大32トークンとした。

VLMに画像端の状態まで判断させると、「球が画像の下方にある」ことを「下端で切れている」と誤認した。このため、対象の認識はVLM、画像端との接触はOpenCVによる指定色の画素領域で確認する。複数球への接近では、VLMが中央の球を右と誤認し続ける例もあった。指定対象が見えるというVLMの回答を条件として、細かな移動方向には画素による追跡を使う。VLMの回答と画像処理による追跡方向を区別し、画像処理で補った結果をVLM単独の性能として扱わない。

### 認識とタスクの評価を分ける

球の正解座標をVLMや移動判断に渡さない。得点評価だけはMuJoCoの実状態を使い、球全体がポストとクロスバーの内側でゴールラインを越えたかを確認する。得点後は停止指令へ切り替える。球の位置・速度を直接書き換えて得点させる処理はない。

また、同じ画像に赤・青の2指示を与え、画像を変えずに指示だけで選択対象が変わるかを比較した。対象色が不在の場合も評価し、別の色の球で代用しないことを確かめた。

## 4. 実行結果

Apple SiliconのMacで実行した。実行環境はPython 3.12.7、MuJoCo 3.10.0、ONNX Runtime 1.31.0である。推論時間は実時間、移動・得点時刻はシミュレーション時間として区別した。

赤球が左、青球が右にある2球シーンで、青球を指定して自動運転した。成功した試行では、8回の実VLM推論を経て青球がゴールを通過し、停止指令へ切り替わった。試行中は手動移動へ切り替えず、赤球の水平位置は初期位置（0.70 m、0.20 m）に残っていた。

| 確認項目 | 結果 |
|---|---|
| 対象と認識 | 青球を指定し、Qwen3-VLによる画像推論を8回実行 |
| 接近動作 | 右旋回、前進、左への修正旋回を挟んで青球へ接近 |
| 押し込み開始 | 試行開始から67.180シミュレーション秒 |
| 得点・停止指令 | 72.465シミュレーション秒に `GOAL`、前進・旋回指令ともゼロ |
| 得点後の運動 | 約2秒後のロボット水平速度は約0.0073 m/sまで低下 |
| 非対象の赤球 | 初期位置に残り、得点していない |

推論時間は初回22.139秒、以降7回は4.918〜6.988秒だった。成功例でもVLMの左右判定には誤りがあり、画像処理による追跡で移動方向を補っている。したがって、これはVLM・画像処理・歩行方策を組み合わせたシステム全体の成功例であり、VLM単独の制御性能を示すものではない。

接近後に押し込み条件を満たさず停止した試行もある。確認できた成功は1試行であり、安定した成功率を示すものではない。成功試行の頭部カメラは垂直画角45度だった。現行実装の60度への拡張と下端での向き直しを含む設定は、別途実VLMでの確認が必要である。

単球の正面配置でも、3回の実VLM推論を経て27.31シミュレーション秒に得点し、停止指令へ切り替わったことを確認した。また、中央・左・右・視野外・画像下端で切れる5枚では、方向と画像境界の判定がすべて期待値に一致し、保存画像での推論時間は2.39〜4.28秒だった。

対象選択の確認として、垂直画角45度のカメラで左右の入れ替えと対象色の不在を含む4画像に赤・青の指示をそれぞれ与えた。8件中7件で方向と停止条件が期待値に一致し、2球がある4件では指示に応じて選択方向がすべて切り替わった。推論時間は2.81〜3.84秒だった。残る1件は左の赤球を中央と誤認した。これは静止画像での行動候補の確認であり、対象選択から得点までの成功率を示すものではない。

2球の物理試験では、画像認識を投影計算で代用し、実際の歩行方策と接触物理を動かした。推論待ちを3・4.5・7秒とした各1試行で、青は3条件、赤は2条件で得点し停止した。赤の7秒条件では球が横へそれた。これは制御と接触の確認であり、実VLMの認識を含む成功率ではない。押し込み中は再観測しないため、接触時のずれに対応できない点が残る。

## 5. 反省点と今後の課題

単球の正面配置では、画像を見ずに直進する方法でも成功しうる。このため、正面中央を空けて赤・青の球を左右に置き、指定した青球への旋回・接近・得点を確認した。ただし、画像を使用しない手法や画像処理だけの手法との比較実験は行っておらず、VLMを使う優位性までは示していない。

実VLMを含む青球の成功例は得られたが、赤球の実VLMによる得点や、配置を変えた反復試行は確認できていない。旋回量の左右差、接触による球のずれ、近距離での見失いが課題となる。認識・追跡・接触のどこで失敗したかを分けて評価し、押し込み中も球のずれへ対応する必要がある。

色選択自体は従来の画像処理でも実装できる。本実験はVLMの優位性を示すものではなく、文章による対象指定を既存モデルの認識と行動候補へ接続する試みである。また、短い回答形式でも形式崩れや誤認は起こるため、構造の検証と画像処理による確認を併用する必要があった。

既存モデルの推論周期が異なる問題や、認識結果をそのまま動作に使う難しさを、物理シミュレーションで確認できた。教育用のタスク設計やロボット制御の試作に応用できる構成だが、実機や照明・遮蔽物のある環境での性能は検証していない。

## 6. 再現方法

依存関係と素材を取得した後、2球から青を選ぶ自動運転を起動する。READYの表示後、Space、数字の8の順に押す。

```sh
uv sync --extra vision
uv run python scripts/fetch_assets.py
uv run --extra vision python -m duckscout --policy --soccer blue
```

`blue` を `red` に替えると対象が変わる。色を省略した `--soccer` は単球のシーンを使用する。上記は現行実装の起動方法であり、実行結果に記載した成功試行との設定差は前述のとおりである。

詳細な操作と対象選択の比較手順は[README](https://github.com/nszknao/physical-ai-applied-1-final/blob/main/README.md)、制御と評価の仕様は[設計文書](https://github.com/nszknao/physical-ai-applied-1-final/blob/main/docs/design.md)を参照されたい。
